Test extraction limits on xz and tar.xz archives too

The suspected bug, xz extraction failing with NoClassDefFoundError because
org.tukaani:xz would be missing from the archive-cache class path, isn't real:
plexus-archiver 4.14.0 depends on org.tukaani:xz 1.12 with the runtime scope,
so xz is on the run-time class path of archive-cache, of its tests, of the
CLI, and of the library users of coursier-archive-cache (Maven turns a
runtime dependency of a compile dependency into a runtime one). It is only
missing from the compile class paths, which is why test code creating xz
archives with XZCompressorOutputStream didn't compile, and why
ArchiveCacheLimitsTests left xz out.

Add org.tukaani:xz 1.12 (the version plexus-archiver asks for) to Deps, and
to the archive-cache test module only, then add xz and tar.xz archives to
ArchiveCacheLimitsTests, so that the size / entry limits are checked for them
too. The main module's dependencies, and so the published POMs, the shaded
JARs and the CLI native image, are unchanged.
---

## Was the issue confirmed?

No, not as a run-time bug. Only the compile-time part of the description is real.

- `./mill show 'archive-cache[3.3.8].runClasspath'`, `'archive-cache[3.3.8].test.runClasspath'`
  and `'archive-cache[2.13.18].test.runClasspath'` all list `org/tukaani/xz/1.12/xz-1.12.jar`.
  The `compileClasspath` and `test.compileClasspath` tasks don't.
- The plexus-archiver 4.14.0 POM declares `org.tukaani:xz:1.12` with `<scope>runtime</scope>`.
  commons-compress 1.28.0 declares `org.tukaani:xz:1.10` as `<optional>true</optional>`. 1.12
  is the version actually resolved, so that's the one I used.
- The network tests in `ArchiveCacheTests` for `txz` (GNU hello tar.xz) and `xz` pass. They
  were neither skipped nor failing silently:
  `./mill -i 'archive-cache[3.3.8].test.testOnly' coursier.cache.ArchiveCacheTests` → 18/18
  passed, `txz` and `xz` included. Selectors like `coursier.cache.ArchiveCacheTests.txz` aren't
  accepted by this Mill `testOnly` ("Test selector does not match any test"), so I ran the
  whole class.
- The new generated `xz` / `tar.xz` cases in `ArchiveCacheLimitsTests` extract fine in the
  "within limits" test, which confirms at run time that there's no NoClassDefFoundError.
  The test isn't "failing before, passing after": before the change it doesn't compile, and
  only because of the test-side compile class path.
- CLI: `./mill show cli.runClasspath` already includes xz-1.12 (not on `cli.compileClasspath`,
  which the CLI doesn't need). So the bug doesn't show up for library users or for the CLI.

## Changes

- `mill-build/src/coursierbuild/Deps.scala`: new `Deps.xz = org.tukaani:xz:1.12`, with a
  comment saying why it's there and that it must follow plexus-archiver's version.
- `build.mill`: `archive-cache[_].test.mvnDeps` adds `Deps.xz`. The main module is unchanged.
- `ArchiveCacheLimitsTests.scala`: adds an `xz` compressor and the `tar.xz` (multi-file) and
  `xz` (single-file) archives, and removes the comment explaining why they were left out.

## Native image / shading / assembly

Main dependencies are unchanged, so nothing changes for publishing, shading or the native
image. I still checked:
- `Shading.scala` is only mixed into `paths` and `core.jvm` (shading directories-jvm), so
  archive-cache isn't involved.
- `Check.scala` checks the namespaces of shaded / proguarded JARs. Its interface proguard /
  JarJar rules in `build.mill` already rename `org.tukaani.xz.**` to `coursierapi.shaded.xz`,
  so xz was already bundled there.
- `modules/cli/src/main/resources/META-INF/native-image` has no xz-specific config. xz is
  pure Java with no reflection or JNI, and it was already on the CLI class path, so the native
  image is unaffected.

I didn't build the native image or the assemblies, since that wasn't needed for a test-only
dependency change.

## Follow-ups

- If archive-cache ever drops plexus-archiver, xz must become an explicit (runtime) dependency
  of the main module, or `.xz` and `.tar.xz` extraction would break. A Steward bump of
  plexus-archiver that changes its xz version should come with a bump of `Deps.xz`.
